## Codebase Patterns
- Schema contract defined in `pipeline/config.py`: always import column lists, types, and constraints from there.
- Warehouse layer (`pipeline/warehouse.py`) enforces WAL journal mode and foreign keys.
- Idempotency pattern: Truncate-and-reload per run snapshot keeps tables deterministic across re-runs.
- SQLite + PostgreSQL dual compatibility: Standard ANSI SQL queries run cleanly across both.
- Python 3.14 JSON serializability: Boolean values in DQ summary must be cast to `int` (`0`/`1`) or `str` before json.dumps.
- Data Quality Gate: Pure functions in `pipeline/silver/quality.py` return `DQResult` dataclasses; zero mutation of inputs.
- Test Execution Rule: Always execute pytest from repository root (`HealthGuard-AI/`) so relative fixtures (`data/hospital/hospital_data.csv`) resolve properly.
- Silver column naming: After `transform_to_silver(cfg)`, columns are snake_case (patient_id, cost, condition, age_band, readmission_flag). Use `managed_connection(cfg.warehouse_db)` + `pd.read_sql_query` to load the Silver DataFrame in test fixtures.
- DuckDB `_resolve_col`: Engine must dynamically resolve actual column names from DESCRIBE to handle Bronze (PascalCase) vs Silver (snake_case) differences.
- Hive partitioning: `export_partitioned_parquet` uses PyArrow `ds.write_dataset` with `partitioning_flavor="hive"`. DuckDB reads back via `read_parquet('**/*.parquet', hive_partitioning=true)`.

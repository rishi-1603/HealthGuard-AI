# Model Honesty Audit
### Why the readmission model's AUC is ~0.99 — and why that is NOT skill

> Generated by `scripts/model_honesty_audit.py`. Same train/test split as
> the shipped model (random_state=42, stratified). Reproducible on demand.

## The numbers

| Configuration | AUC | What it means |
|---|---|---|
| **Shipped RandomForest (all 6 features)** | **0.992** | The headline number |
| Trivial baseline: per-Condition readmission rate | 0.929 | No ML — a lookup table |
| Model WITHOUT Condition | 0.986 | Label still leaks via Procedure |
| Demographics/utilization only (Age/Gender/Cost/LOS) | 0.985 | Label even leaks via Cost/LOS |

## Diagnosis

1. **Condition → Readmission is nearly deterministic.** 11 of 15 conditions have a readmission rate above 95% or below 5%. Heart Attack → 100% readmitted; Heart Disease → 98.5%; most others → 0%.
2. **Procedure is a 1:1 proxy for Condition** (15/15 conditions map to exactly one procedure), so removing Condition alone doesn't help.
3. **Cost and Length of Stay follow the condition pathway too**, so even demographics-only models recover the label (AUC ≈ 0.98).

## Conclusion (the honest framing)

- Real-world clinical readmission models achieve **AUC 0.65–0.75**. AUC ≈ 0.99 here is a property of the **synthetic data-generation process**, not predictive skill.
- What this project genuinely demonstrates: the **end-to-end system** — training pipeline, per-patient scoring, SHAP explainability, and serving — with honest evaluation. The number is trivially high *and we say so*.
- Any reviewer who checks (and good ones will) finds the note in the UI, this audit, and the README all telling the same story.

# Model Card — Readmission Risk Classifier

> **HealthGuard AI** · synthetic hospital dataset · educational demo
> **Not a medical device. Not for diagnosis, treatment, or clinical decision-making.**

## 1. Model details

| | |
|---|---|
| **Task** | Binary classification — predict `Readmission = Yes` for a patient record |
| **Algorithm** | `RandomForestClassifier` (scikit-learn), 100 trees, `random_state=42` |
| **Features (6)** | `Age`, `Gender_enc`, `Condition_enc`, `Procedure_enc`, `Cost`, `Length_of_Stay` |
| **Training code** | `scripts/train_readmission_model.py` (shipped model) · `src/models/train.py` (legacy reference) |
| **Artifacts** | `readmission_model.joblib`, `encoders.joblib`, `metrics.json` (this directory) |
| **Reproducibility** | Fixed seed, stratified 80/20 split; CI retrains and re-evaluates on every push |

## 2. Intended use

- **In scope:** educational demonstration of an end-to-end ML workflow — training pipeline, per-patient scoring, SHAP explainability, calibration checks, fairness slices, and honest evaluation.
- **Out of scope:** any real clinical, operational, or insurance use. The dataset is synthetic (984 patients, generated by `scripts/generate_data.py`); labels do not come from real hospital records.

## 3. Training data

| | |
|---|---|
| **Source** | `data/hospital/hospital_data.csv` — synthetic, 984 patients × 10 columns |
| **Label** | `Readmission` (Yes/No) — 26.8% positive rate (264 patients) |
| **Known structure issues** | `Condition → Readmission` is nearly deterministic in the generator (11/15 conditions >95% or <5% readmission); `Procedure` is a 1:1 proxy for `Condition` |

### Baselines — read these before praising the AUC

| Baseline | AUC | Interpretation |
|---|---|---|
| Per-condition readmission-rate lookup (no ML) | **0.929** | A trivial lookup table already scores 0.93 |
| Model without `Condition` | 0.991 | Label still leaks via `Procedure` |
| Demographics/utilization only | 0.985 | Label still leaks via `Cost`/`LOS` |

**Full audit:** `reports/model_honesty.md` (regenerated by `scripts/model_honesty_audit.py` in CI).

**Honest conclusion:** AUC ≈ 0.99 is a property of the synthetic data-generation process, not predictive skill. Real-world clinical readmission models achieve AUC 0.65–0.75. The value of this project is the *system* — training, scoring, explainability, evaluation, and the discipline to report why the headline number is not trustworthy on its own.

## 5. Explainability & fairness

- Per-patient SHAP attributions in the live dashboard ("why this score?").
- Cohort-level SHAP analysis: `reports/cohort_shap.md`.
- Slice metrics (AUC/precision/recall by age group and gender): `reports/fairness_check.md`.
- Fairness slices on synthetic data are illustrative of the *method*, not evidence of real-world fairness.

## 6. Limitations

1. Synthetic labels are near-deterministic given condition — metrics do not transfer to real patients.
2. Six features only; no comorbidities, medication history, prior admissions, or social determinants.
3. No temporal validation possible — the generator has no realistic time dimension for readmission.
4. Probability outputs are uncalibrated for clinical use; thresholds are not clinically validated.
5. SHAP explanations describe the model's behavior on synthetic data, not clinical causality.

## 7. Ethical use

Disclosed as synthetic everywhere it appears (UI footer, README, reports). No claim of clinical effectiveness, patient benefit, or cost reduction is made anywhere in this repository. See `reports/assumptions_and_limitations.md`.
